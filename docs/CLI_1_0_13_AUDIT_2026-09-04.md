## 3. 本轮已实现的兼容和可靠性修复

1. **版本策略不再是“全部未知补丁一刀切”，也不盲信外部替换。**
   - 公开源码审计范围为 `1.0.0–1.0.13`。
   - 未来同一 `1.0.x` 补丁只允许由用户点击固定目标更新，并在本机通过 initialize、session/new、close、delete 等 live 门禁；通过回执会绑定到当前 Desktop 数据目录。
   - 用户在应用外直接替换为未知补丁，没有本机通过回执时，普通会话启动仍失败关闭。
   - `1.1+` 和未知主版本继续失败关闭。
2. **Updater 事务可恢复。** 更新期间阻止应用退出；目标更新、必要回滚和会话恢复完成前不销毁控制器。会话恢复错误只作为 warning，不再覆盖已经成功、失败或回滚的主要回执。
3. **MCP Elicitation。** 支持官方 camelCase form/URL 反向请求；只允许 HTTPS 或 localhost HTTP；Schema、字段、字符串和总响应都有上限；Stop/退出发送 `cancel`。完成通知同时校验 Session、elicitation ID 和可选 Server 名。
4. **图片感知读取。** 对源码审计的 `1.0.4–1.0.13` 不声明宿主文本 `readTextFile`，避免把 CLI 的图片读取吞成文本；未知未来补丁仍采用保守能力集。
5. **稳定客户端身份。** ACP initialize 和 prompt 元数据统一携带 `clientIdentifier=grok-build-desktop`，方便 CLI 正确采用桌面附加策略。
6. **长文本草稿附件竞态。** 每次提交携带随机 `submissionId`；主进程只分离匹配世代的草稿行，并在会话缓存复制期间保护该世代的源文件。旧提交不会删除/覆盖用户同期新建的下一条正文或附件，预处理完成后新草稿自动保存继续。
7. **上游跟踪。** 快照更新到 stable 1.0.13、公开仓库和 SOURCE_REV；同一未 live 验证版本不会每周重复追加完全相同的 Issue 评论，新 stable 仍会触发维护项。
8. **依赖安全。** 通过根级 overrides 固定已修复的 `@xmldom/xmldom 0.9.12`、`fast-uri 4.1.4` 和 `qs 6.16.0`；完整 high-level npm 审计为 0，未借机升级 Electron/TypeScript 主版本。

## 4. 暂不实现、不能伪装为已支持的部分

- **原生共享队列迁移。** 1.0.6+ 的版本化队列能最终替换 Desktop 本地队列，但当前安装版 1.0.3 对这些 mutation 返回 `Method not found`。必须先抓取 1.0.13 live `queue/changed`，再做本地 ID 与 CLI `id/version/owner` 的确定性迁移和重启恢复。
- **Hook 确认反向请求。** 1.0.13 Changelog 已确认产品行为，但 Desktop 还没有精确、稳定的请求/响应 Fixture；未知请求只记录方法、Schema 版本和大小，不记录正文。
- **Workflow 控制。** pause/resume/stop 只能使用 CLI 返回的真实运行显示名/ID；没有 live 列表前不添加会误操作的按钮。
- **Always/Never 规则。** 只呈现 CLI 权限卡返回的选项和范围，不根据命令字符串自行生成永久 Glob。
- **1.0.13 live 验收。** 仍需用户在更新中心明确点击“更新并验证”；失败时按固定旧版本回滚。

## 6. Updater 严格度结论

原策略对任何超出 `maxVerifiedVersion` 的补丁直接拒绝，安全但会迫使 Desktop 为每个 CLI 补丁发版；完全放开 1.x 又会重演 IPC/队列/图片读取不兼容。现在采用折中：

1. 已审计版本走离线合同；
2. 未审计的后续 `1.0.x` 只走用户触发的固定目标更新；
3. 更新后先做 live ACP 门禁，失败回滚；
4. 成功回执按当前 Desktop 数据目录持久化，后续启动才允许；
5. `1.1+` 必须等新的 Desktop 兼容档案。

这比仅比较 App/CLI 版本号更可靠，也没有取消用户控制和回滚边界。
