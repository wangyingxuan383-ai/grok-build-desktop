# CLI 1.0.40 对齐与发布后修正（2026-09-21，未发布）

用户已授权修复并通过代理升级本地 CLI。本轮以已发布 v0.9.6 为基线；未提交、发布新 Desktop 版本或替换已安装 Desktop 应用。原 Grok 审查文档保留，建议逐项评估后采用。

## 完成的修正

- R1：清理失效或 fresh 会话映射时携带定义 revision，避免覆盖运行期间的新配置。
- R2：绑定会话在准入后变忙时释放全局槽位，等待空闲后重新竞争；权限/Computer 临时配置在最后的空闲检查后应用，结束恢复原配置。
- R3：Host 退出、急停、会话释放中止对应 Computer 确认；中止信号接入持久确认。迟到批准不能恢复已停止的 Computer 操作。确认创建与清理使用运行事务，同一运行的旧请求退出不清除其他待确认状态。
- 对话内显示属于当前会话的定时任务确认，与收件箱共用确认 ID；运行提前记录会话关联。没有待确认时不额外遍历全部任务与运行历史。
- MCP 新建任务默认关闭 Computer，明确 GUI 任务可传 computerEnabled；独立任务可更新该项，绑定任务保留执行配置。保留用户要求的绑定工作区编辑，不增加 Auto 模式的重复批准。
- 表单支持 IANA 时区；全局能力证据明确标记为汇总。原生恢复按 spawn_subagent.resume_from 的实际观察记录，消息工具出现不等于恢复已验证。
- CLI 已被外部升级时可直接“验证当前 CLI”，仍须通过真实路径/版本/哈希绑定的 ACP 核心检查，不扩大离线版本白名单。

## 本机 CLI 与官方变化

- Desktop 未设置自定义路径，实际选择 `%USERPROFILE%\.grok\bin\grok.exe`。
- 经本机已配置代理调用官方更新器：09-20 从 1.0.30 升到 1.0.34；09-21 stable 检查更新为 1.0.40，继续升级成功。
- 最终版本：**1.0.40 (eb1a2256660d)**。
- SHA-256：`034C883FA3962AB6CA409C2D3C7501C642166535DD39FA936ECFFE1AC2CAD92E`。
- 通过生产 CliUpdateService 执行 initialize/new/resume/close/delete，核心通过并记录本机 approved identity。未发送 session/prompt、未调用模型。未终止已有用户会话。
- 真实 CLI 1.0.34 首次加载会话插件时 hooks/list 为空；官方 hooks/action reload 后才能列出插件 Hook。适配器现检查已注入 Desktop MCP 会话的精确插件 Hook，仅在缺失时 reload 并复查；不自动信任额外插件，也不绕过调用证明。1.0.40 复查同样通过。
- 1.0.40 相比本轮 1.0.34 握手多出 `x.ai/session/setup`；官方公开源码将其定义为 session/new 阶段通知。适配器记录诊断，不把它伪装成可调用 RPC。
- MCP 列表新增 `sessionMcpResolved`。为 false 时尚未解析会话配置，未就绪条目显示“初始化中”，暂不允许误操作开关。
- 两版均声明 `x.ai/capabilities`，直接调用均返回 -32601；不能仅凭声明就作为可调用接口开放。
- [官方更新日志](https://x.ai/build/changelog) 本轮可读内容到 1.0.34，含 MCP 名称/结构化结果/取消行为及子会话随父会话关闭等修正。当前公开源码快照 `4247f661689354b831191f11eeeac8424993fe3d` 标为 1.0.38，并非 1.0.40 的精确源码。不能将这些材料合称为 1.0.40 完整发行说明。
- 官方 [子智能体文档](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/16-subagents.md) 的恢复、条件消息能力及 MCP 继承与本机端到端验证分开记录，未建立第二套调度器。
