## 2. 设计原则

1. **安静、密集、可操作**：长会话、高信息密度，靠文字层级而不是边框和颜色区分层次。
2. **同一位置做同一件事**：模式切换永远在侧栏顶部；会话相关的辅助内容永远在右侧窗格；设置永远是整页层。
3. **重要的东西不折叠**：子智能体、失败、待确认是一等公民，直接出现在对话流里；普通工具调用收进一行"已处理 N 步"。
4. **子会话就是会话**：用同一个会话组件只读渲染，不另写简化列表（ZCode `SubagentSessionSidePane` 的做法）。
5. **不让校验挡住官方能力**：登录、切换账号由官方 CLI 完成；桌面只在确有故障时阻止，并给出可执行的修复按钮。

## 3. 设计规范（token 草案见 `tokens.css`）

- **表面层级**：窗口/侧栏 `--color-window` → 主框/侧窗格 `--color-frame` → 卡片 `--color-card` → 浮层 `--color-popover`；悬停/选中使用半透明叠加。
- **字号**：只由 `--ui-font-size`（默认 14px）推导 `xl 18 / lg 16 / base 14 / caption 13 / sm 12 / xs 10`；字号设置不再修改 `html` 字号。代码、终端、差异保留独立字号。
- **圆角按嵌套递减**：外框/卡片 12 → 控件/菜单 8 → 菜单行/嵌套控件 6 → 4；输入框外壳、对话框、Toast 用 16。
- **控件高度**：24 / 28 / 32 / 36；图标 16 为基准。
- **颜色语义**：主按钮单色（深色主题白底黑字，浅色主题黑底白字，符合 Grok 品牌）；蓝色只用于焦点、链接、运行中；成功/警告/危险只用于真实状态；子智能体头像色只表示身份，不表示状态。
- **图标**：统一改用 lucide-react（MIT），替换 34 个手绘 SVG 和 `›`、`⌄`、`×`、`◆` 等文字符号。
- **基础组件**（新建 `components/ui/`）：Button（primary / secondary / ghost / danger / link，sm/md/lg/icon）、IconButton、Input、Textarea、Select（Radix）、Switch、Checkbox、Badge、SegmentedControl、Card、EmptyState、Toast；现有 Menu / Dialog / Tooltip / Popover 按新规范重做样式。
- **用户自定义主题保留**：六色种子映射到新的语义 token。

## 4. 信息架构

```
┌侧栏 264px─────────┐┌主框（会话 / 图像会话 / 图库 / 页面）──────┐┌右侧窗格（标签）──┐
│[编程|图像] 分段切换 ││标题 · 项目 · 分支        改动 终端 编辑器 ▣││子会话 文件 改动 … │
│新建会话    Ctrl N   ││                                          ││                  │
│搜索        Ctrl K   ││   对话（阅读宽度 760）                    ││ 同一会话组件      │
│定时任务 / 技能与扩展 ││                                          ││ 只读实时渲染      │
│项目                 ││                                          ││                  │
│ ▾ 项目 A            ││                                          ││                  │
│    会话 1  ● 运行中 ││                                          ││                  │
│    会话 2           ││                                          ││                  │
│      ↳ 子智能体      ││   [ 输入框 · 模型 · 推理 · 模式 · 发送 ]    ││                  │
│    已归档 (4)       ││                                          ││                  │
│ ▸ 项目 B            │└──────────────────────────────────────────┘└──────────────────┘
│其他来源 Codex/Claude │
│头像 · 用量 · 设置    │   设置 = 覆盖主区与侧栏的整页层，左侧分类导航
└─────────────────────┘
```

- **侧栏**：顶部分段切换【编程｜图像】，两种模式共用同一外壳，只替换侧栏列表和主框内容，因此永远能切回。项目以树形列出并直接嵌套会话（取代"选择工作区"下拉＋独立列表）；子智能体会话嵌套在父会话下；归档按项目折叠；Codex/Claude 会话收进"其他来源"。开发工具入口（终端、浏览器、产物、Worktree、Memory、Persona、Profiles、看板）移出侧栏：高频的进入标题栏和右侧窗格，低频的进入设置或命令面板（Ctrl K 仍可全局搜索到）。
- **标题栏**（44px）：会话标题（点击改名/菜单）、项目与分支标签；右侧为改动统计、终端开关、在编辑器中打开、右侧窗格开关、更多。
- **右侧窗格**：常驻、可调宽、带标签的面板，取代现在的覆盖式抽屉和"侧栏工具"卡片菜单。标签类型：子会话、子智能体目录、文件、差异/改动、计划与结果、浏览器、终端输出、产物预览、会话信息。标签支持关闭、右键菜单、拖动排序。
- **取消顶部"工作区标签行"**：项目切换走侧栏。主框一次显示一个会话或页面；并排查看通过右侧窗格完成。现有四窗格分屏代码暂不删除，后续按 ZCode 分屏方式再评估开放。
- **设置**：整页层，左侧分类导航（通用、外观、账号与用量、模型与提供商、定时任务、技能与扩展、Computer Use、Grok CLI、诊断、关于），取代现在"页面中套带 × 的卡片 + 面包屑 + 返回会话"三重返回。

## 5. 各模块设计

### 5.1 对话
- 用户消息：右对齐卡片；附件/参考图缩略图在正文上方。
- 助手工作过程：一行"已处理 · N 步 · 用时 · 读取 X 个文件、搜索 Y 次"，展开后为竖线串起的步骤列表（图标＋动作＋路径）；运行中自动展开最后几步。
- 最终回答：正常 Markdown 阅读排版，不再套"最终回答"标签卡。
- 待确认、失败、Computer 状态就近出现在对话流中，不另开浮层。

### 5.2 子智能体
- **合并为一张卡**：`spawn_subagent` 工具调用与 `subagent_spawned/progress/finished` 生命周期事件按 `parent_prompt_id ↔ promptId`、`subagent_id`（解析自工具结果）和描述合并为一个实体。
- **卡片直接出现在对话流**（不进"已处理"折叠）：头像色、标题、类型·模型、状态徽标（运行中计时/完成/失败/已停止）、当前动作（正在读取某文件）、工具次数；完成后可展开"任务 / 结果（Markdown）/ 用时·回合·工具·Token"。
- **操作**：打开会话（在右侧窗格以子会话标签打开）、停止（仅在 CLI 支持取消时显示）、继续追问（仅在 CLI 声明消息能力时启用，否则说明原因）。
- **子会话 = 真会话**：复用主对话的回合组件只读渲染；头部显示类型、模型、状态、父会话链接；运行中实时更新（不再在适配层丢弃子会话通知，或跟随 `updates.jsonl` 增量读取）。
- **数据补全**：读取 CLI 写入的 `subagents/<id>/meta.json`、`output.json`，即使父会话不是在桌面里打开的也能列出历史子智能体；修正后台子智能体在回合结束时被误标为完成、迟到事件落到孤立回合、看板字段被后续事件清空等问题；子会话不再作为普通会话出现在侧栏顶层，而是嵌套在父会话下。

### 5.3 图像模式
- **一个图像会话 = 一个持久的真实 CLI 会话 + 一个固定文件夹**：首次生成用 `--session-id`，后续用 `--resume`，不再每次删除会话，使"把背景换成蓝色"能带上上下文；每个会话的原图保存在自己的子目录，改保存根目录不拆散旧会话。（`--single` 与 `--resume` 组合需一次实机确认；若不支持，退回为桌面端显式附带上一轮描述和所选结果。）
- **会话页是对话流**：用户描述气泡（含参考图）→ 结果图网格（悬停：下载、复制、删除、"以此继续修改"）→ 元信息（路由·工具·用时·再来一组）。失败是一张就地错误卡：原因、"重新登录"（登录类错误）、重试、删除这条记录。
- **输入框**：参考图、比例、数量（仅在模型支持时显示）、路由（默认 Grok CLI，Provider 需手选）、生成。
- **图库是独立页面**：瀑布流，只展示成功的图片；筛选（全部 / 图像会话 / 代码产物）、排序、按描述搜索；悬停显示描述和所属会话；"选择"模式批量导出、删除、作为参考图新建。
- **删除**：可删单张图片、单次生成、失败记录、整个会话；删除时明确选择"仅移除记录"或"同时删除原图文件"，默认仅移除记录。
- 会话标题取首条描述并可改名，不再每次生成都被覆盖；空会话不落盘。

### 5.4 账号与 CLI 兼容
- **登录与账号不再受兼容门禁约束**：官方 CLI 登录成功即保存；随后的连通性验证只作提示，失败不回滚已成功的新凭据。
- **修正版本比较**：所有门禁统一使用规范化版本号。
- **门禁改为"提示为主"**：新 CLI 版本基础握手（initialize + session/new）通过即可正常使用；未实测的扩展能力只显示提示；只有握手失败才阻止新建会话，并在界面给出"重新验证 / 回滚 / 选择其他 CLI"。
- 账号页：账号列表（当前/切换/移除）、添加账号（设备码卡片显示代码、倒计时、复制、取消）、用量条、CLI 状态说明。

## 6. 分阶段计划

每阶段结束：定向测试 + 类型检查 + 构建 + 打包后深/浅色 × 1366×768 / 1920×1080 截图核对，并把截图给你确认后再替换桌面版（保留回退副本）。新写和重写的文件采用正常可读的格式，不再沿用单行压缩写法。

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **P0 急修** | ① 登录门禁：规范化版本号、登录不经门禁、验证失败不回滚成功登录；② 图像产物解析只接受工具结果中的产物，不把输入参考图当产物；③ 图像单条记录/失败记录/单张图片删除接口（先接入现有页面） | 你能用新版正常登录/添加账号；失败的图像记录能删除 |
| **P1 设计系统与外壳** | 新 token 与字号体系、lucide 图标、基础组件；新外壳：侧栏（模式切换、项目树、底栏）、标题栏、框架化布局、右侧窗格框架与标签；统一的外壳路由状态；设置整页层；逐区删除被替换的旧 CSS | 编程模式外观与原型一致；两种模式切换位置统一、可来回切换；旧抽屉与工作区标签行移除 |
| **P2 对话与子智能体** | 工作过程折叠行与步骤列表；子智能体合并卡片；子会话在右侧窗格用同一组件实时只读渲染；读取 meta/output；侧栏嵌套；子智能体目录标签；状态与字段修正 | 使用子智能体时对话里直接可见、可展开、可点开成完整会话；运行中实时刷新 |
| **P3 图像模式** | 持久 CLI 会话与固定目录；对话流会话页；新输入框；独立图库页；完整删除能力；标题与空会话处理 | 能在同一会话多轮修改；会话页与图库形态区分明确；任何记录都能删除 |
| **P4 其余页面迁移** | 账号、提供商、定时任务、扩展与技能、Memory、Persona、Profiles、文件/改动/Git/Worktree、诊断、引导、创作迁移到新组件；CLI 门禁改为提示为主并提供修复入口 | 所有现有功能在新界面可达且操作真实连通 |
| **P5 收尾** | 删除残留旧样式与重复代码、更新布局回归测试、全页面截图矩阵、打包与桌面替换 | 无旧样式残留；验收截图齐全 |

## 7. 需要你确认的决策

1. 取消顶部"工作区标签行"，项目切换走侧栏；文件、差异、子会话、浏览器等内容标签统一进入右侧窗格；四窗格分屏暂不开放。
2. 图像会话绑定真实 CLI 会话以获得多轮上下文（后续轮次会带上下文，Token 消耗会高于现在的一次性调用）。
3. CLI 兼容门禁改为"提示为主"，登录与账号完全不受门禁影响。
4. 引入 lucide-react 图标库。
5. 主按钮采用单色（Grok 黑白），蓝色仅用于焦点、链接与运行状态。
