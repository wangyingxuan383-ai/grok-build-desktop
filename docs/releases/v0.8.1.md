# Grok Build Desktop v0.8.1｜紧急修复版

本版本紧急修复 v0.8.0 中会阻断日常使用的三项回归，建议所有 v0.8.0 用户立即更新。

## 简洁说明

- 修复新建任务发送时因 `projectId` 被 IPC 拒绝而无法创建会话。
- 修复设备码登录把 OAuth API 地址误显示为浏览器验证页面；代理和网络错误现在会给出明确中文原因。
- 修复项目迁移/重新绑定对 Grok Build CLI 1.0.0 调用不存在的 Fork 方法，导致所有历史会话显示 `Method not found`。
- 项目重新绑定改为复制完整会话目录、在新位置真实恢复验证后再提交；失败时保留原会话。

## 详细说明

### 新建会话

新任务草稿中的 Desktop 内部字段不再直接透传给严格 IPC。首次发送现在只提交 CLI 会话创建真正支持的工作区、模型、Provider、思考档位、模式和执行档案字段。

### 账号登录

设备登录只会把真正面向用户的验证页面交给浏览器，不再把 `/oauth2/device/code`、Token 等 API 端点当作登录链接。若本机代理不可用、连接被拒绝或网络超时，界面会显示可操作的中文诊断，同时仍由 CLI 1.0.0 单独负责打开一次浏览器，避免双窗口。

### 项目路径重新绑定

当前 Grok Build CLI 1.0.0 运行时没有声明 `session/fork`，旧实现盲调标准/私有 Fork 方法，因而批量返回 `Method not found`。v0.8.1 改为：

1. 事务复制完整、不解析的官方会话目录到新工作区映射；
2. 使用当前 CLI 在目标目录真实 Resume；
3. 只有恢复成功后才更新 Desktop 的执行档案、投影、Token 和路径绑定；
4. 失败时清理目标副本并保留原会话；
5. 未来只有运行时明确声明标准 Fork 能力时才调用该接口。

## 验证

- 102 个测试文件、740 项离线测试通过；6 个真实环境测试文件、9 项按设计跳过。
- TypeScript、生产构建、公开源码扫描、Renderer 分块、Native Host、Electron Fuses 和打包版 UI 验收通过。
- 本机 Grok Build CLI 1.0.0 无推理探针确认：标准与旧私有 Fork 均不可用，而完整会话目录复制后可在新工作区真实 Resume。

## 升级说明

- 可直接覆盖安装 v0.8.0，现有会话和设置会保留。
- 安装包尚未签名，Windows 首次运行可能显示 SmartScreen 提示。
- 如果登录仍提示 `127.0.0.1` 代理连接失败，请先启动所配置的本机代理，或在应用设置中清除失效代理。
