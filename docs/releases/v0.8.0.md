# Grok Build Desktop v0.8.0｜正式版

> 发布构建补充：完整 UI 夹具由同一提交的 PR/main CI 与本机打包门禁执行；标签构建对 unpacked 应用执行 Fuses、ASAR/Renderer/资源哈希静态验收，再从同一目录生成 Setup/Portable 并校验结构，避免把 Hosted 无交互桌面无法调度打包 Renderer 误判为产品故障。

这是自公开版 **v0.6.22** 以来的集中大版本更新。0.8.0 完成 Grok Build CLI 1.0.0 适配，并系统收口会话恢复、Plan/权限/停止、并行任务、自定义 Provider、文件审核、媒体、更新中心与高频桌面交互。

## 简洁版

- 完整适配 Grok Build CLI 1.0.0：受控跨主版本更新、运行时能力门禁、会话恢复/关闭、MCP 1.0 事件、Compact、Plan、Stop 和官方会话能力。
- 会话更可靠：本地投影先显示，失败或取消保留部分回答；草稿、队列、附件、媒体、Token、模型/模式与运行状态可恢复。
- 多会话可并行运行，后台任务不会污染当前输入框、停止按钮、滚动位置或草稿。
- 自定义 Provider 支持 OpenAI Chat、Responses、Anthropic Messages 与 Gemini 转换，包含增量 SSE、工具、五档思考、结构化错误和能力扫描。
- Git 与非 Git 项目均可查看真实改动；项目路径移动后可离线查看并重新绑定，文件、Review、媒体和打开位置统一走可信路径。
- 新增会话搜索、Context/Usage/Session Info、手动 Compact、CLI/应用更新检测、Grok Doctor 安全修复预览与上游变化跟踪。
- UI 与可访问性继续收口：响应式右栏、长脚本/表格/Diff 独立滚动、CJK 复制、项目去重/隐藏、草稿优先和模型动态刷新。

## 详细版

### 1. Grok Build CLI 1.0.0

- Desktop 启动的 ACP、媒体、自动化和能力探针统一禁止 CLI 自行更新；只有更新中心能执行固定目标更新。
- 0.x → 1.x 被识别为跨主版本升级，必须人工确认；升级前保存活动会话，升级后验证 `initialize`、新建/恢复/关闭/删除及核心能力，失败时回滚精确旧版本。
- 新建、加载和恢复会话会提交明确的交互附加策略；解析 1.0 的结构化 `closeOutcome`，不再把所有关闭结果压缩为一个布尔值。
- 兼容直接通知和包装通知，接入 MCP 初始化、工具变化、服务器状态、服务器列表及完成事件；事件严格归属于其会话。
- 官方 Git 状态请求显式包含未跟踪文件、统计、补丁和子模块策略；运行时不支持时使用现有受限系统 Git 后备。
- 适配官方 Session Rename/标题所有权的前向协议；当前 stable 1.0.0 未提供该方法时继续使用本地标题，不伪造官方同步。

### 2. 会话、Plan、权限、Stop 与队列

- 会话保存模型、Provider、本地模型 ID、上游别名、思考档位、模式和执行档案；重新打开旧会话不再被全局默认覆盖为 Grok 4.5。
- Provider 路由、凭据或网关初始化失败时停止发送并显示真实原因，不静默回退官方模型。
- Plan 决定使用一次性回执：批准、继续规划或取消成功后立即关闭卡片，模式切换异步结算，重复点击不会产生第二个回答。
- Plan 模式只自动允许读文件、搜索、列目录及受限只读命令；写入、危险命令和未知工具不会被伪装成只读操作。
- 队列和插话保存 queued、accepted、running 与终态，重启后同 CLI 状态确定性合并；已经被 CLI 接受的条目不会提供虚假的“撤回”。
- 普通回合、Plan、权限/问题等待、Compact、队列和插话共享幂等停止链路；迟到事件不能重新唤醒已停止的回合。
- 每个已加载会话拥有独立运行时；两个以上会话可以并行，后台完成只更新所属会话。

### 3. 正文恢复、草稿与项目

- ConversationProjection V2 保存可见用户/assistant 块、过程、工具、计划、错误、媒体、队列、会话配置、回合终态和精确 Usage。
- 本地正文先于 ACP 恢复显示；流式中退出、失败、取消、`session-reset` 或第三次重开不会仅剩耗时/Token 指标。
- ACP 回放按稳定 Block ID 合并，重复、旧块和迟到事件不会制造第二份回答；损坏投影和磁盘异常有明确降级。
- 新建任务采用草稿优先：首次发送前不创建 CLI Session；正文、附件和运行参数重启后仍可恢复，首次发送只迁移一次。
- Windows 项目路径按大小写、尾斜杠和可解析链接去重；项目可隐藏/恢复而不删除会话。
- 原项目路径失效时可先离线阅读，再通过事务式重新绑定恢复；不会直接编辑官方会话 JSONL，也不会默认恢复旧代码状态。

### 4. Provider 与模型兼容

- 主进程回环网关支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 与 Gemini GenerateContent/SSE 的文本、图片、工具、工具结果、思考、Usage 和错误转换。
- 跨协议 SSE 使用增量状态机和背压，不缓存完整长回答；支持 UTF-8 半包、多工具调用、Usage 尾包、空 Delta、取消与错误事件。
- 模型能力、协议编码和会话选择分离；思考档位按真实证据显示，未知模型不套用虚假的固定能力。
- Provider/模型可以独立启停；受管模型显示“提供商 · 模型”，不会同官方模型混淆，也不会删除后自动切回官方默认。
- 能力扫描支持单模型/当前 Provider、阶段进度、取消和部分证据；扫描结果只有经过用户选择才写入配置。
- HTTP、Provider、路由、Trace 与受限响应详情可折叠查看；普通日志和支持包不保存凭据或请求正文。

### 5. 文件、Review 与媒体

- Git 项目优先使用官方状态/文件/Diff 证据，能力缺失时使用安全 Git 后备；非 Git 项目使用 TurnFileChangeJournal 展示真实写入前后变化。
- Review 采用文件索引、搜索和单文件懒加载，不一次渲染大量 Diff；文件/区块操作继续校验快照和可信路径。
- 最近文件、工具卡、Review、编辑器、媒体与顶栏“打开位置”统一使用会话或 Worktree 的真实执行根目录。
- 媒体支持 Auto、CLI 和自定义 Provider 路由；产物只有复制到会话缓存、验证文件头后才生成消息卡。
- 多图使用有界画廊；图片可预览、复制和另存，视频通过范围读取提供，不整体加载到 Renderer。
- 超过 12,000 字符的粘贴内容可以转为可恢复文本附件，发送失败仍保留。

### 6. 更新、诊断、使用信息与界面

- 应用可在启动及 24 小时间隔检查正式 GitHub Release；CLI 检查显示当前/稳定版本和跨主版本风险，但更新始终需要用户点击确认。
- 增加 Context、Usage Limit 与 Session Info 视图；只展示 CLI/Provider 返回的精确数据，缺失时标记未知而不推算。
- 支持继承 CLI 或按会话设置 60%–95% Compact 阈值，并提供“立即压缩”；时间线记录自动/手动、开始/完成/失败/取消。
- Grok Doctor 显示结构化诊断；自动修复只接受 CLI 报告的安全 ID，经短时一次性令牌、重新校验和二次确认执行。
- 本地全文搜索覆盖用户消息、最终回答、计划标题、文件名和错误摘要。
- 右栏按 Review、计划/结果、文件、任务、媒体和会话信息映射真实功能；长脚本、表格、代码和 Diff 不再撑破面板。
- Renderer 保持 `nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`；文件、进程、Git、Provider、凭据、媒体和剪贴板均留在主进程。

## 验证与下载

- Windows x64 提供 Setup 与 Portable 两种资产。
- `SHA256SUMS.txt` 校验安装包、便携包、SBOM 与第三方许可证报告。
- Setup 与 Portable 同时提供 GitHub 构建来源证明（Artifact Attestation）。
- 最终源码门禁：101 个测试文件、734 项通过；6 个 live 文件、9 项按设计跳过。TypeScript、资源/生产构建、公开扫描、Renderer 分块、Native Host、Electron Fuses、依赖审计与 UI 回归通过。
- 正式发布工作流会从标签提交重新构建、扫描、创建草稿、回下载验证 SHA-256/Attestation，全部成功后才发布为 Latest。

## 已知边界

- 安装包暂未使用商业代码签名证书，Windows 可能显示 SmartScreen 提示。
- 当前测试中的远程 CPA 上游明确返回 `403 cpa_local_only`；Desktop 已显示真实原因，但这不是成功推理证据。
- stable 1.0.0 当前未提供部分官方源码快照中的可选方法（如 Session Rename、ACP Git status/Usage）；相应控件保持关闭或使用已验证后备，不按版本号伪造能力。
- 外部 Provider、MCP、企业策略、GPU/DPI 和特定超长会话仍受各自环境影响；未执行的付费/live 测试不会被计入已验证项。
