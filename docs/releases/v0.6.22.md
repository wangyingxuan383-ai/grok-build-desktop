# Grok Build Desktop v0.6.22

这是自公开版 **v0.6.6** 以来的一次集中更新，合并了 v0.6.7–v0.6.22 的本地验收成果。重点是自定义 Provider 兼容、会话可靠性、并行任务、文件审核、媒体创作和桌面交互。

## 简约版

- 自定义 Provider 支持 OpenAI Chat、Responses、Anthropic Messages 与 Gemini 协议转换，并加入逐模型协议、思考档位、代理和超时配置。
- 修复 CPA、自建网关与 Anthropic 兼容链中的鉴权、模型回退、工具 Schema、无签名 thinking、长响应断开和错误归因问题。
- 会话正文、部分回答、错误、工具、媒体和 Token/耗时会本地投影保存；重开会话不再只剩一行指标。
- 多个会话可以同时运行；排队、置顶跟进和插话状态不再被全局发送锁串行化。
- 非 Git 项目也能查看 Agent 的真实文件改动和 Diff；Git Review、最近文件、跳转和编辑器边界得到修复。
- 媒体中心支持 CLI/自定义 Provider 路由、会话内图片缓存、多图画廊、复制/另存；历史图片改用安全本地协议显示。
- 新增 Claude 接力、Provider 深度兼容扫描、Token 活动、结构化错误、Codex 风格决策卡及多项设置/诊断改进。

## 详细版

### 1. 自定义 Provider 与模型兼容

- 主进程回环网关可在 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini GenerateContent 之间转换文本、图片、工具、工具结果、思考、Usage、SSE 与错误。
- Provider 和模型可分别选择客户端协议、上游协议、兼容家族、Schema 档、代理策略、思考传输、可用档位和 30–3600 秒推理空闲超时。
- 修复 Desktop 托管模型被恢复成官方 `grok-4.5`、CLI bearer 覆盖自定义凭据、环境变量 Header 未刷新、Provider 标签与真实路由不一致等问题。
- Gemini/严格模式会清理空枚举、空类型和不兼容 Schema；Anthropic 合法签名 thinking 保持透传，只有缺失签名的异常块才安全降级为普通思考文本。
- Grok 4.5 可使用 `minimal / low / medium / high / xhigh`；未知模型不会被强行套用固定档位。
- 深度兼容扫描改为可恢复 Job，支持单模型或当前 Provider 范围、阶段进度、可靠取消、部分证据保留、协议/工具/Usage/媒体/思考检测和选择性应用。
- Provider 与单个模型都可停用；零模型 Provider 可以保存，停用项不会进入模型选择器、默认模型或 CLI 托管路由。

### 2. 会话可靠性、错误与 Token

- 新增会话可见投影：用户消息、assistant 流式正文、思考、过程、工具、计划、权限、错误、图片/视频、回合状态与精确 Usage 会追加保存并定期原子快照。
- 失败、取消、进程重建或 `session-reset` 后保留已经显示的部分回答；重开会话时与 ACP 回放按稳定块 ID 合并，避免正文消失或重复。
- 旧会话只有耗时/Token 而缺少正文时会尝试可靠恢复；无法确定归属时明确说明，不伪造内容。
- 每个回合显示真实耗时与 Provider 提供的精确 Token；没有明细时只显示总量，不估算输入/输出。
- 错误卡默认折叠，展开后显示脱敏的 HTTP、Provider、路由、Trace、阶段、响应摘要和建议操作。
- Free 滚动 24 小时额度与周/月额度分离，未知或过期数据不会被猜测成可用余额。

### 3. 计划、权限、队列、插话与并行会话

- 计划批准、继续规划和取消按请求 ID 幂等；只回答原 ACP 请求一次，不再生成 `[Plan approved]` 的第二条 Prompt。
- 权限、问题和计划卡提交成功后立即移除；陈旧请求在本地收起，不会再次调用已经结束的请求 ID。
- Plan 模式自动放行明确的读、搜索、获取、思考与受限只读命令；写入和未知操作仍需用户决定。
- 队列编辑、删除、重排和置顶跟进都有回执。已被 CLI 接受的插话会标记为不可撤回，不再提供无效叉号。
- 插话是同一 ACP 会话的高优先级后续回合，不是额外启动一个 Desktop Agent；当前回合收束后会建立独立用户消息、回合边界和运行状态。
- Renderer 提交锁改为按会话隔离。每个已加载会话继续拥有独立 Grok CLI/ACP 进程，多个任务可以并行运行，后台完成不会覆盖当前会话草稿、附件、焦点或滚动。

### 4. 文件审核、Agent 改动与导航

- 读取当前 Grok Build ACP 的标准嵌套 Diff 内容，保留真实 old/new 文本并计算逐文件增删行；读/搜索工具不再被误算为修改。
- Git 项目保留 Unstaged、Staged、Commit、Branch 与 Last turn；非 Git 项目显示 Agent 的真实本回合/全会话改动，不伪造暂存、提交或分支能力。
- Agent 改动默认使用紧凑 unified Diff、自动换行和有界文件列表；右侧 Dock 窄窗口不再遮挡内容。
- 最近文件、工具卡、Review 和编辑器统一按会话或 Worktree 的真实执行根目录跳转；越界、缺失和外部文件显示行内原因。
- 文件/Diff 工作台提供明确“返回会话”，导航完成后重新计算虚拟列表与 Composer 尺寸。

### 5. 图片、视频与媒体中心

- 媒体中心支持自动、Grok CLI 和指定自定义 Provider/模型路由；CLI 仅允许 `image_gen`、`video_gen`、`image_to_video` 和 `reference_to_video`。
- 媒体任务使用独立临时 Grok 会话，解析 streaming-json 的真实文件/URL，验证后复制到原会话缓存，再清理临时会话，不污染侧栏。
- 修复相对路径 `images/1.jpg` 被截断、合法临时会话产物被误判为工作区外，以及 sandboxed Renderer 无法加载 `file://` 图片的问题。
- 历史图和新生成图通过主进程受控的 `grok-media:` 协议显示；支持大图、复制、另存、打开原文件和多图有界画廊。
- 长文本超过 12,000 字符时可转为会话草稿 `.txt` 附件，发送失败仍可恢复。
- Zero Data Retention 团队的视频接口若要求 `output.upload_url`，Desktop 会保留真实错误并停止重试；需要非 ZDR 团队或实现上传回调的视频 Provider。

### 6. 桌面界面、账号与工具

- 会话壳层拆分为 Sidebar、TopBar、Composer、Right Dock 与独立弹层；开发工具默认折叠，输入框、背景、消息和右栏响应式边界统一。
- 权限与计划采用紧凑的 Codex 风格临时决策面，但只展示 Grok CLI 实际支持的选项。
- 新增 Claude Code 会话只读索引和“在 Grok 中继续”，原 Claude JSONL 不被修改。
- 多账号列表使用内部滚动、活动账号置顶与窄窗换行，设备码登录只保留一个浏览器所有者。
- 更新、CLI 检查、诊断与脱敏日志导出都有运行、成功、失败和取消状态。
- 日志、支持包与本地 JSON 存储加强脱敏、轮转、损坏恢复和原子写入；Renderer 继续保持沙箱、上下文隔离和关闭 Node 集成。

## 验证与下载

- Windows x64 提供 Setup 和 Portable 两种资产。
- `SHA256SUMS.txt` 可校验安装包、便携包、SBOM 与许可证报告。
- GitHub Release 同时提供构建来源证明（attestation）。
- 本地候选通过 80 个离线测试文件、465 项测试；5 个 live 文件/8 项按设计跳过。TypeScript、生产/资源构建、原生 Host、自检、公开扫描、Fuses、安装版与 Portable 探针通过。

## 已知边界

- 安装包目前未使用商业代码签名证书，Windows 可能显示 SmartScreen 提示。
- ZDR 团队的视频生成需要上游接受 `output.upload_url`；当前官方 CLI 工具链无法替 Desktop 自动补齐该回调。
- 不同自建 Provider 对工具、思考、SSE 和媒体协议支持不同，建议在 Provider 管理器内先做单模型检测，再应用确认过的能力。
