# 桌面 Agent 体验改进方向

评估日期：2026-10-02。参考官方产品文档与当前实现；下列条目是开发机会，不代表已交付功能。已有完成提醒、任务记录、右侧 HTML 预览、截图反馈、图库比较和 PR/CI 状态应先完善使用闭环。

## 优先级与完成条件

| 优先级 | 改进方向 | 当前基础与缺口 | 可核验的完成条件 |
|---|---|---|---|
| 高 | 让模型真正使用开发预览 | 已有手动浏览器、服务器启停和截图反馈；尚无专用模型浏览器工具 | 模型可发现并使用 DOM、截图、点击、输入与日志工具，操作绑定正确项目；用户能看到验证证据 |
| 高 | 统一活动与确认入口 | 通知、收件箱、队列和任务记录已具备，但状态仍散布多个页面 | 一个入口筛选运行中、等待确认、失败与未读；点击返回具体任务、图像或会话，状态不重复计数 |
| 高 | 子智能体完整协作 | 原生状态、只读子会话与父会话跟进草稿已具备；各版本消息/取消/恢复合同仍需验证 | 显示可靠父子身份、动作和结果；真实合同决定可用操作；父子用量不会重复累加 |
| 中 | 图像版本和资产整理 | 已有完整草稿、请求复用与两图对比；作品来源和修改分支不够清楚 | 原图、参考图和衍生版本可追溯；支持命名、收藏、批量导出；记录删除和文件删除保持明确 |
| 中 | 任务模板与下次执行解释 | 已有时间预设、固定账号/上下文与运行历史 | 可保存带参数的任务模板；展示下次执行时间、时区、是否需要登录/桌面以及错过触发的行为 |
| 中 | 项目知识导航 | 已有文件树、搜索与 Memory | 可生成附源码引用的项目概览，标注更新时间和过期内容；不会把生成说明当成真实源码事实 |
| 中 | 审查结果闭环 | 已有 Git、Diff、Worktree 和 PR/CI 查看 | 问题关联具体文件与行、处理状态和复查结果，减少反复描述上下文 |
| 后续 | 跨设备与云端执行 | 当前核心是 Windows 本机 CLI 和调度器 | 单独建设身份、环境、文件同步和执行服务；不要用 UI 入口宣称机器关机后本地任务仍会运行 |

## 借鉴依据

- 官方 [ChatGPT/Codex 通知与活动视图](https://learn.chatgpt.com/docs/notifications)区分完成提醒和等待输入，并聚合运行、未读与待回应会话；当前项目已具备提醒，下一步重点是活动入口统一。
- 官方 [Claude Code Desktop](https://code.claude.com/docs/en/desktop#preview-your-app)将开发服务器预览与模型截图、DOM 操作和验证结合；当前项目的手动预览需要补模型工具连接，才有相近闭环。
- 官方 [ZCode 任务与文件管理](https://zcode.z.ai/en/docs/task-management)提供分组、工作区、时间线以及带引用的项目 Wiki；适合进一步降低多项目导航成本。
- 官方 [ZCode 子智能体](https://zcode.z.ai/en/docs/subagents)可作为协作交互参考；Grok 仍沿用自身原生调度和合同，不能直接照搬另一产品的工具名与能力声明。

## 实施边界

优先补齐高频操作和真实能力验证，再扩大面板数量。浏览器控制、自动验证、远程执行等需要新服务端能力，应独立设计并验收。不要自动消耗模型额度、切换收费 Provider 或升级 CLI 来证明界面完成。
