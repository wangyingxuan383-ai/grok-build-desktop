### 自审时额外收口

- 精确重试不得残留失败副本；迁移提交快照附件时不能把另一条失败记录的附件替换为当前草稿附件。
- 空目录清理使用非递归 rmdir，避免检查为空后删除新出现的附件。
- 部分会话恢复后重试跳过已恢复实例，避免重复 ACP。
- 挂起前的后台清理和日志同时失败时，仍在 finally 释放 ACP，不遗留占用 CLI 二进制的子进程；新增故障注入回归。
- 强制保留状态也阻止认证/普通诊断 ACP；认证探针移除直接删官方目录的旧实现。
- 手动回滚与重新验证不依赖 stable 查询；本机验证授权核对探针前后二进制哈希和版本，防止验证过程中外部替换。
- 恢复清单不落盘环境变量/凭据，实际重连时从主进程现有执行档案重新构建。

## 确认的问题（待修复）

### R1 / P1：发送后的自动保存仍可能删除失败恢复所需的长附件

位置：`src/main/app-controller.ts:1863–1872`、`src/main/services/ui-state-service.ts:94–109,251–257`、`src/renderer/src/App.tsx:747–767`。

复制到会话缓存后立即释放源文件保护；`detachDraftForSubmission` 删除草稿行，但没有维持待结算源文件租约。Renderer 进入 sent 阶段后自动保存空内容或下一条内容，会调用目录清理，把旧长文本文件删除。若 Prompt RPC 随后失败，Renderer 仍用原附件路径恢复草稿，而不是已物化缓存路径。

**隔离复现已确认**：创建文本附件 → 带 submissionId 保存 → detach → 模拟发送后空自动保存 → 检查源文件，结果 `sourceStillExists:false`。这不依赖真实 CLI，也不是模型服务故障。

修复方向：源附件租约覆盖整个失败恢复窗口，或返回并使用持久会话缓存引用；不能只保护复制阶段。补充失败晚于自动保存、用户输入下一条、切会话三种端到端时序。

### R2 / P1：新任务草稿显式恢复绕过已有世代检查

位置：`src/renderer/src/App.tsx:528–580`，重点 `552–561`。

新加的 `getDraft` 回包直接执行 setComposer、clearAttachments、setNewTask。期间有多个 await，却没有验证当前目标、打开请求世代或用户编辑版本。点击新任务后立即打开历史会话、换项目或输入文字，旧请求返回时可覆盖当前 Composer；当前草稿自动保存还可能把错误内容写入另一个目标。

这是新增路径绕过 `useSessionDraft` 中已有 `shouldApplyDraftHydration` 的静态可达竞态。原 UI 探针通过不证明迟到 IPC 安全。应复用唯一 hydration 所有者并增加延迟回包测试，而非再增加一套无保护赋值。

### R3 / P1：无法解析 CLI 版本时反而绕过失败关闭

位置：`src/main/services/grok-process-manager.ts:637–645`。

新增门禁仅在 `parsedCliVersion` 为真时执行。读取失败、空输出或不可解析输出会继续创建 ACP，无法证明运行的不是未支持版本，与“未知版本失败关闭”的声明相反。应区分明确支持的旧版本与版本读取失败，后者给出可重试诊断，不应默认放行。

### R4 / P1：更新异常路径的日志失败跳过回滚和会话恢复

位置：`src/main/services/cli-update-service.ts:356–360,386–395`。

本轮把会话恢复从 finally 移出；更新失败、版本复查也失败时，直接 await 日志写入。一旦日志目录不可写或磁盘满，日志异常跳出整个流程，不再执行后面的精确回滚/restoreSessions，且覆盖原始下载错误。

**隔离故障注入已确认**：注入下载失败、版本复查失败、日志失败，返回只有 `disk log failure`，`restores=0`。未调用本机更新器。应把恢复放回保证执行的结算段，诊断写入失败只能附加而不能决定事务控制流。

### R5 / P2：会话菜单的迟到关闭事件可清空其他菜单

位置：`src/renderer/src/components/SessionListRow.tsx:52`、`Sidebar.tsx:93`。

受控 details 的 onToggle 同时响应用户操作和 React 改 open。旧行关闭时无条件调用 `setOpenSessionMenu("")`，不核对关闭的是否仍为当前行；迟到事件可把刚打开的另一行菜单关闭。方向键处理也未在 summary 上先打开菜单。当前测试只静态渲染 HTML，并未验证浏览器 toggle 时序和焦点。

修复方向：关闭采用基于当前 ID 的函数式更新；或由显式 summary 按钮驱动受控状态，避免 DOM toggle 回灌；使用真实 DOM 交互测试。

### R6 / P2：MCP 表单丢弃约束却声称 Schema 受支持

位置：`src/main/services/grok-acp-adapter.ts:3129–3177`。

归一化只保留 type、enum、default 等，忽略 minimum/maximum、minLength/maxLength、pattern/format 及组合约束，仍可能返回 `schemaSupported:true`。用户可提交上游明确禁止的值，再收到服务端失败。要实现约束验证或明确拒绝不支持的约束，不能静默丢弃。

另外本机 HTTP URL 的 IPv6 hostname 实际含方括号，当前 `::1` 比较不能接受 `http://[::1]`；属于小型兼容缺口。

### R7 / P2：测试会话清理未覆盖异常和可选探针

位置：`src/main/services/cli-update-service.ts:445–491,518–532`，`grok-plan-mode.live.test.ts` 的 finally。

主探针只在成功路径删除 session，finally 只关闭 adapter 和删除工作目录；可选 Computer 探针创建第二个会话却只 dispose。Plan live 测试也只 dispose。这是延续下来的清理缺口，本次实际残留与这些路径一致，不能把它归为全部由最新 UI 新增。

应在获得 session ID 时登记，并在每个探针的 finally 尝试官方删除；保留主要错误和清理诊断。删除命令返回 0 也需检查“已删除”与“未找到”的区别。

### R8 / P2：更新页的徽章与真实检查状态不一致

位置：`src/renderer/src/components/AppAuxiliaryPanels.tsx:130–135`。

无论尚未检查或检查失败，只要 updateAvailable 不为真就显示“稳定”。检查失败文字和“稳定”徽章可同时出现；也未独立展示验证/回滚/恢复阶段。应使用明确的未检查、检查中、失败、可更新、当前领先、已最新状态，而非二值徽章。

## 规划声明与覆盖缺口

- App Shell/Dialog Host 是结构拆分；App 仍承载打开/发送事务。不能称完整 Conversation/Submission Controller 拆分已经结束。
- App 仍订阅整个 sessions 数组；会话行传入每次新建的闭包，因此 memo 不能证明后台事件仅重渲染所属行。
- 新增 SessionListRow、Composer、Toast、About 测试主要为 `renderToStaticMarkup`；没有真实验证 Tab/Esc/方向键、菜单焦点恢复、点击后的异步失败。
- 此次未重跑有真实会话创建的 live 测试，也未执行安装版验收。1.0.13 仍为离线/源码证据，不等于本机已验证 1.0.13。
